# Phase 4 Slice 8a: static overloading, the mechanism (implemented)

Retire the hand-written, type-directed builtin dispatch in `check_operator` /
`check_term` into a real overload **table**, so a user overload of a builtin
name (`: + ( Vec2 Vec2 -- Vec2 ) ;`) becomes *reachable* at a call site instead
of being accepted, lowered, linked, and never dispatched to. A refactor with
exactly one new observable behaviour; everything else is byte-for-byte identical.

## Key anchors (as shipped, `src/check.rs` unless noted)

- `struct BuiltinRow { inputs, outputs, lower }` and `enum BuiltinLower`
  (`Add Sub Mul DivFloat Mod And Or Xor Not Shl Shr Cmp(CmpOp) Max MaxTotal
  Print`) — the entry type (Q-A).
- `fn builtin_table() -> HashMap<String, Vec<BuiltinRow>>`, memoized as
  `static BUILTIN_TABLE`. Rows generated by iterating `numeric_types()` (12:
  eight fixed ints + `usize`/`isize` + `f32`/`f64`), `int_types()`,
  `float_types()`, `printable_types()` (15: numeric + `bool`/`str`/`cstr`).
  `shl`/`shr` are `(T, i64 -- T)`.
- One resolution entry point over the merged candidate set, called from **both**
  `fn check_term`'s probe chain and `fn poly_delegate_op` (R6).
- `fn check_operator` shrinks to the numeric operand-class **coercion +
  diagnostic fallback** (not deleted).
- `Module::builtin_overloads: HashMap<Span, String>` — sparse per-call-site
  record of sites resolved to a user overload of a builtin name, mirroring
  `Module::instantiations`/`CallInst`. Filled in `fn check`, consumed by
  `MirBuilder::lower_call` (`src/ir.rs`), threaded via `empty_builtin_overloads()`
  on paths with none.
- Untouched by this slice: `check_shuffle`, `>T` conversions, `len`/`fill`/`cstr`
  (`check_str_word`/`check_array_word`), and everything `drop`
  (`find_drop_overloads` + its `check_duplicate_word_names` exemption; both die
  in 8b).

## Requirements

**R0 — Scope.** Only overload-by-operand-type dispatch moves into the table:
`check_operator`'s arithmetic tower, comparisons, `max`, `max-total`, `.`. Out
of the table (stated reasons, byte-for-byte preserved): `check_shuffle` (fully
generic, not an overload set; `drop` is 8b); `>T` conversions (name-parsed
target, no operand key); `len`/`cstr`/`fill` (`PolySig`-shaped / single
candidate). The retired match is *dispatch-selection*; operand-class validation
and coercion survive as a fallback.

**R1 — No shadowing.** A user overload whose inputs **exactly** match an
existing candidate (builtin/local/imported) is a located error, not silent
override. `check_duplicate_word_names`' key widens `(module, name)` →
`(module, name, input_types)`: identical keys keep today's `duplicate word`
message byte-for-byte; differing input types no longer collide. Admitting them
is only half the rule: the checking env holds a candidate *list* per name and
resolves by exact operand match, or the second definition would displace the
first and leave it unreachable (exit criterion 4). Each candidate is minted
under its own lowering symbol (`ast::overload_symbols`), since two bodies under
one name would otherwise collide at the assembler. The same check
rejects a def whose `(name, input_types)` equals a **builtin row**:
`error: overload of `+` (line 2, col 3) has the same input types (i64 i64) as a builtin`.
One check, wider key: no exemption class, no deletion.

**R2 — Exact beats coercion.** The resolver runs an exact-input-type pass across
all candidates first; only on an exact miss does numeric coercion (`unify_pair`)
run. Adding an overload cannot silently steal a previously-coercing site.

**R3 — Overloads imported, not carried by the type.** Importing `Vec2` does not
bring `+`. A named word with candidates but no operand match (exact or coerced)
→ located resolution error, never silent fallback. For a builtin operator this
**is** today's `operand_pair_mismatch_error` byte-for-byte; for a user
non-operator name, `no_overload_matches_error` lists what the name does accept
(`error: no overload of `show` in `main` (line 3) accepts these operands`,
followed by one `candidate:` line per candidate's inputs).

**R4 — One arity per name in scope.** All candidates (builtin rows + locals +
imports) must agree on input count; disagreement is a located error at the
**second** candidate's site (def when local, import when imported), never a
call-site ambiguity. Local via an arity-agreement pass in
`check_duplicate_word_names`:
`error: overload of `+` (line 2, col 3) takes 1 input but another `+` takes 2; all overloads of a name must agree on input count`.
Import via the `selective_collision_error` family in `check_selective_imports`.

**R5 — Concrete/generic overlap rejected, not ranked.** A poly candidate
(`: + ( 'T 'T -- 'T )`) beside any concrete candidate of matching arity
(builtin row or `env`) is rejected at the second site. Poly effects are empty
(signature in `PolySig`), so R1 never fires — distinct check comparing
`poly_env` names against `builtin_table` rows + concrete `env` entries:
`error: generic overload `: + ( 'T 'T -- 'T )` (line 2, col 3) overlaps a concrete overload of `+`; a name cannot mix a generic and a concrete candidate`.
Module-scoped like R1/R4 (`(module, name)`, decided after this spec was first
written): a builtin candidate is in scope everywhere, but a local concrete
candidate only overlaps a poly candidate declared in its own module — an
unrelated same-named concrete word in a different, non-importing module does
not collide. A same-module collision, or one reached through an actual
unqualified import, is unaffected (the latter already rejected generically by
`check_selective_imports`' local-collision check, independent of poly vs.
concrete).

**R6 — Table-driven exact-match, coercion fallback.** `check_term`'s Call
handling replaces the `check_operator` probe with one resolution step:

1. **Operand read** — top `n` types (`n` = agreed arity); underflow →
   `underflow_error`. `reject_quotation_operand` (R11 guard) fires here first.
2. **Exact pass** — one matching candidate wins: builtin row → its
   `BuiltinLower`; user/imported word → ordinary `Instr::Call` path. R1/R4/R5
   guarantee ≤1 match, so no ranking.
3. **Coercion/diagnostic fallback (numeric operators only)** — on exact miss,
   run that operator's operand-class guard + `unify_pair`: success → coerced
   row's lowering; `NeedsSizeConversion` → `size_conversion_needed_error` (X10
   verbatim); class failure → the operator's specific diagnostic
   (`operand_pair_mismatch_error`, `div_requires_float_error`,
   `mod_requires_int_error`, `bitwise_*`, `shift_*`, `max_over_float_error`,
   `max_total_requires_float_error`). `.` has no coercion: miss →
   `print_requires_printable_error`.

   Both call sites route through one extracted resolution function
   (`check_term` chain **and** `poly_delegate_op`): a poly body calling `+` on
   two `Vec2` is the same call as anywhere. A Phase 1 obligation — the corpus
   has poly bodies using operators, so leaving the second site fails R9 at once.

**R7 — Lowering dispatches to the resolved candidate.** `lower_call` consults
`Module::builtin_overloads` first: a recorded span emits `Instr::Call` to the
recorded symbol and returns; unrecorded sites take the existing name-directed
arms unchanged. The corpus produces no records, so its lowering is literally
untouched. Lowering never re-runs resolution (checker is the single source).
The map records any overloaded call, not only builtin-named ones, and
`ir::lower` keys its env by the same per-candidate symbol the checker recorded,
so the two cannot disagree about which body a call reaches. `lower_line` /
`lower_word` are threaded with it too: without that the REPL accepted an
overloaded call and then lowered it as the builtin, which segfaulted the
session rather than merely failing to dispatch.
The poly-body dispatch path (`poly_delegate_op`, `poly_call_term`'s own `env`
lookup) mirrors this: a builtin-named exact match found there is recorded
onto the same `Module::builtin_overloads` map, keyed by the poly body's own
(instantiation-invariant) call-site span, so every monomorphization of a poly
word calling a user-overloaded operator on a concretely-typed operand
dispatches correctly too.

**R8 — `extern:` unchanged.** An `extern:` redeclaring a builtin stays a located
error (`check_extern_redeclaring_a_builtin_is_error`). `is_builtin_word_name`
may read the populated table, but the rejection is unchanged; `extern:` gains no
overload path.

**R9 — Corpus byte-for-byte (first-class exit).** Every golden and
`examples/*.sth` compiles to byte-identical QBE and program output, sole
exception the new `Vec2 +` program. Baseline captured in `tests/qbe_baseline.rs`
(+ `tests/qbe_baseline/{gcd,factorial,strings,refs,resources}.ssa`).

## Answered open questions

**Q-A — entry type: concrete rows only.** An entry carries a lowering
(`BuiltinLower`), because several rows per name share `(inputs, outputs)` but
differ in codegen (`.`'s 15 rows all `Print`; a user `.` a `Call`) — so not
`Sig`. Generic builtins (`len`/`fill`/`>T`) stay hand-written; building
`PolySig`-shaped entries + a numeric/`Ord` bound for candidates no user
overloads this slice is the premature abstraction rules 5/6 refuse. Entry shape
does not preclude a later generic variant (the deferred view-type `len`
candidate would add a `BuiltinLower` variant + a sibling generic form). Accepted
cost: table is not yet the home of all builtins.

**Q-B — `unify_pair` runs before the coercion lookup, as a per-operator fallback
on exact miss; it is not table rows.** Table answers only "defined for these
exact types." Coercion-as-rows would multiply entries and could not reproduce
X10 / per-operator diagnostics byte-for-byte (R9 forbids). Accepted cost:
operand-class predicates + diagnostics stay as code, so `check_operator` shrinks
to the fallback rather than vanishing.

## Out of scope (hard boundary)

Everything `drop` (8b; keep its registry + exemption, do not delete as tidying);
output/return-type overloading; traits/type-classes/non-static dispatch; the
deferred view type; moving any builtin onto `extern:` (`.` stays `Instr::Print`,
only its key changes); generic table entries / a `Bound`-style category
mechanism; REPL builtin-overloading as a demonstrated feature (`typed_env` must
adopt the new shape without regressing REPL goldens, but user builtin-overload
dispatch *in the REPL* is not an exit criterion). Note that being outside the
exit criteria did not license crashing: the REPL accepted such a call and
lowered it as the builtin, taking SIGSEGV, so the resolution record is threaded
through its lowering path and it now dispatches.

## Exit criteria

1. `check_operator`/`check_term`'s dispatch-selection arms gone; `builtin_table`
   populated with concrete rows.
2. Corpus byte-for-byte unchanged (R9), only new behaviour being (3).
3. `type: Vec2 x i64 y i64 ; : + ( Vec2 Vec2 -- Vec2 ) ... ;` compiles, links,
   **and dispatches** on two `Vec2` operands, printing correctly (R6 + R7).
4. Rules 1/3/4/5 each a **located** error with the specified message; no
   definition left silently unreachable.
5. Two symbol-named words in one file compile and link (relies on the merged
   `qbe_name` fix; keep its regression tests green). Stated originally as
   `: + ( i64 i64 -- i64 ) ;` beside `: - ( i64 i64 -- i64 ) ;`, which R1 now
   rejects in that exact form (its inputs equal a builtin row's), so the
   surviving regression test uses struct operand types instead.
6. Two overloads of an ordinary (non-builtin) word name are both reachable,
   each lowering under its own symbol, and a call matching neither is a located
   error naming the candidates (R1/R3).

## Phases (as delivered)

1. **Table + concrete-row dispatch (byte-for-byte refactor).** `BuiltinRow`/
   `BuiltinLower`; populate `builtin_table`; replace `check_operator` selection
   with the R6 step (exact pass + `unify_pair`/diagnostic fallback), extracted
   as **one** entry point called from `check_term` and `poly_delegate_op`; adapt
   all `builtin_table()` callers (`check` env seed, `repl.rs` `typed_env`, three
   test helpers). Corpus byte-for-byte. — `51a6a7b`, `207a848`, `187f192`
   (src/check.rs, src/repl.rs, src/driver.rs, tests/qbe_baseline*).
2. **User-overload dispatch, check-side only.** Merge user/imported words into
   R6 and record resolved call sites per `Span` on `Module::builtin_overloads`
   (`check_term`'s `OpDispatch::UserOverload` arm). The intended consumer,
   `lower_call` (R7), was never actually wired to read the map this phase
   despite the plumbing existing end to end (`FuncBuilder::builtin_overloads`
   threaded through, always populated, never consulted) — every builtin-named
   user overload compiled, linked, and silently mis-lowered through the
   name-directed builtin arm (a segfault for `+`/`-`, a pointer comparison for
   `<`) until a later fix cycle added the actual `lower_call` read. The
   `poly_delegate_op` half of the same gap (a poly body's own operator calls
   never reaching a user overload at all, hardcoded `user_overload: None` and
   an `unreachable!` in its place) was fixed in the same later cycle. Criterion
   3 was therefore not actually met by this phase alone. — `4a8f84b`
   (src/{ast,check,driver,ir,parser,resolve}.rs).
3. **Collision/arity/overlap enforcement.** Widen the duplicate-word key + the
   builtin-row comparison (R1), local arity-agreement pass (R4), concrete/generic
   overlap check (R5), mirror arity/collision into `check_selective_imports`
   (R4 import), route operator no-match to its diagnostic + user missing-overload
   message (R3). — `75684ef` (src/check.rs, tests/phase0.rs,
   tests/phase4_modules.rs).
